Practice planner — in the app

A league's saved practice field requests: how many fields of each kind to ask the city for, which nights, at what times — with daylight warnings for the league's own city. Plans belong to the league, not a season. v1 is the request only: it creates no practice slots and doesn't feed auto-assign. Pro and Elite. The public calculator stays free and unchanged.

Notes for the build

Module — unchanged, and how the app uses it

  • No edits to src/lib/practice-planner/ or src/lib/sun/. The app calls computeMode, divisionWarnings, daylightWarnings, seasonTotals, requestText, busiestLabel, seasonRangeLabel directly — not computePlan, whose daylight warnings and sunset line go through cityById (the Sacramento fallback). Daylight is computed only when cityByIdOrNull returns a city; the city id handed to the module is then always a real one.
  • Lit fields without touching the module: daylightWarnings is called with a copy of the input where each lit division's days is []. divisionIsActive then skips it, while the mode result (computed from the real input) keeps its division indexes. Field counts, totals and the request text use the real input. The numbers on this page were produced exactly that way.
  • All sentences on screen are the module's, verbatim. App-only words (lit-fields line, prefill hints, empty states, no-city note, upsell) live in one new pure file in src/lib/practice-planner-app/ or similar — not inside the calculator module.

Storage (needs a migration — not part of this mockup)

  • One table, e.g. practice_plans: org-scoped (owner_id), name, input jsonb (a PlannerInput minus cityId, each division plus lit), mode, timestamps, updated_by. No league_id, no FK to divisions — a plan is a snapshot the admin edits. RLS the 0049 is_org_member form; Pro/Elite enforced in writes, not just the page.
  • The city is NOT stored per plan; every plan reads the league's profiles.sunset_city at render time.

Prefill

  • "Most recent season" = the org's season with the latest start_date, archived or not. One row per division of that season, name copied, team count = that division's live teams rows (never teams.practices_per_week, never divisions.team_count). Other fields start from the calculator's NEW_DIVISION defaults.
  • The "6 in Fall 2026" hint matches by case-insensitive trimmed name; a division with no match starts at 0 teams (not counted) with the amber line.
  • A league with no seasons yet: the planner opens with no rows and "+ Add a division".

Open questions for Whit

  • Nav placement: "Field requests" under Practices (shown), or a tab on the Practices page?
  • Daylight toggle: if Settings → Daylight flags is switched OFF but a city is set, should the planner still show daylight warnings? Mockup assumes yes (the toggle is about game flags).
  • Copy + teams: should Copy offer "Refresh team counts from Fall 2026"? Mockup says no — Copy is an exact duplicate.
  • Request text and lit fields: requestText (unchanged) doesn't mention lights. Fine for v1, or does the city need to know which requests are for lit fields? That would mean an app-side line after the module's text, or a module change.
  • "See plans" on the upsell goes to the existing plan-choice screen — confirm the target.
